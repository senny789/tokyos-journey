# SpriteCast assessment for Tokyo's Journey

Reviewed 20 November 2026 against [SpriteCast commit 52df9dc](https://github.com/Sunghwan0112/spritecast/tree/52df9dcece3f7f797134228f69fd39d328f54ad3). No software was installed and no paid generation was run.

## Recommendation

SpriteCast is useful for consistent side-view **walking** sprites of Tokyo, our female golden retriever. It is not currently a complete generator for her requested walk, run, jump, crouch and sit states. Its animal rendering branch generates a walk and a single rest idle, then returns before the normal action renderer. Its sitting function explicitly rejects animals. Therefore using it for the full character would require extending the quadruped animation code or supplying a separately rigged and animated canine model through another workflow. This is an inference from the implementation, rather than a claim that its advertised humanoid action support also works for dogs. [Animal render branch](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/charpipe.py#L385-L416), [sitting restriction](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/charpipe.py#L744-L751).

For the first playable version, keep our independently generated sprite work moving and borrow SpriteCast's useful principles: fixed camera, fixed frame geometry, shared palette, consistent foot anchors, and animation preview/review. Adopt SpriteCast as a production dependency only if its 3D guide benefits justify the additional model, keys and custom animation work.

## Fit to this game

| Requirement | Verified support and limitation |
| --- | --- |
| Golden retriever on four legs | `kind: "animal"` infers a skeleton from a static mesh instead of buying Tripo's animal rig. A supplied `model_glb` can replace generated 3D. Its procedural walk uses a lateral four-leg sequence; idle is a rest pose with tail raised. Fur and tail deformation still need visual review. [Animal reference](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/reference/character.md#L153-L190). |
| Strict side view | Character rendering uses an orthographic camera, configurable `pitch`, with east at 90 degrees and west at -90 degrees. Setting `pitch: 0` and using east/right-facing output is a plausible strict side-view configuration, but was not executed here. The documented side-scroller preset is 12 degrees down, which shows some top surface. [Camera code](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/render_char.html#L15-L30), [documented views](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/README.md#cameras). |
| Run, jump, crouch | The advertised named actions and imported Mixamo clips belong to the rigged person route. `kind: "animal"` bypasses that action rendering. Faster playback of a walk would not provide an actual running gait. [Branch](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/charpipe.py#L407-L420). |
| Sit | Explicitly people-only in the current code; no canine sit generator. [Restriction](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/charpipe.py#L744-L751). |
| 16-bit pixel aesthetic | `pixelart.py` pixelizes 3D guides, has the image model redraw them, then reads the grid into transparent strips. It supports palette limits, supplied palettes, and an optional pixel editor. Default requested figure height is 96 pixels; sizes below 64 are generated at 64 and reduced. A SNES-like look is a style and palette choice, not a literal 16-color limit. [Pixel workflow](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/reference/pixel.md#the-command), [size behavior](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/pixelart.py#L1-L55). |

## Setup, costs and the free trial

- The package is an MIT-licensed Claude Code plugin. Its Python commands can also be run directly from a checkout; therefore Codex can orchestrate those scripts, but the README does not document a native Codex plugin installation. Python 3.9+, Chrome/Edge or Chromium, and a private virtual environment are required. `doctor.py --fix` provisions dependencies. [Install and direct execution](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/README.md#install).
- Dependencies include NumPy, Pillow, SciPy, Playwright and ONNX Runtime. Character background removal downloads a BiRefNet model; the default lite model is documented as 224 MB. [Requirements](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/requirements.txt), [downloads](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/README.md#what-it-sends-and-fetches).
- Custom drawing needs the user's `OPENAI_API_KEY`; custom animal model generation needs `TRIPO_API_KEY` and Tripo API credits, unless an existing suitable model is supplied. These are separate from Phaser credits and from the built-in image-generation tool. The repository estimates roughly 30 Tripo credits for an animal model and about $0.075 per pixel-art drawing sheet. Run the plan without `--yes` before considering any paid step; estimates are upstream claims, not verified bills. [Character costs](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/README.md#four-legged-animals), [pixel plan](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/reference/pixel.md#the-command).
- The no-key trial re-renders a **bundled prop example** and reuses its already-made drawing. It does not generate a new Tokyo character for free. Existing example rigs can also demonstrate local 3D rendering without generation. [Trial implementation](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/scripts/isoprop.py#L519-L534), [example character rendering](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/README.md#walking-characters).

## Output and Phaser AE integration

Pixel output contains transparent `<clip>-<facing>.png` animation strips, separate shadow strips, `preview.gif`, and `pixel.json` describing frame dimensions and animations. Draw only `east` using `pixelart.py --dirs east` to avoid paying for top-down directions this platformer does not need, then mirror in the game if Tokyo's design is symmetrical. That flag limits drawing, not the animal renderer's initial eight-view output. [Pixel files and flags](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/reference/pixel.md#what-comes-out-characterout-pixelpx).

The ready-made character exporter targets Godot, Unity, Aseprite and **Phaser 3**, not Phaser AE. Its reference also says pixel sets are not yet supported by that character exporter. For this project, consume the PNG strips and metadata with Phaser AE's own asset/animation API; do not import the generated Phaser 3 module into the AE game. [Export contract and limitation](https://github.com/Sunghwan0112/spritecast/blob/52df9dcece3f7f797134228f69fd39d328f54ad3/skills/spritecast/reference/character.md#L19).

## If we adopt it later

1. Keep a neutral, clear-legged Tokyo illustration and a consistent 16-bit palette as source assets.
2. Install the repository locally and run its dependency check; do not use Claude plugin commands inside Codex.
3. Obtain or make a clean four-legged dog model, then render the free side-view walk guides and inspect all four legs before buying drawing.
4. Add actual canine run, jump, crouch and sit poses to a project-owned guide generator, or choose a compatible animated dog rig workflow. SpriteCast's current animal action path will not supply these automatically.
5. Review the unpaid plan, obtain authorization for concrete API costs, generate one side-view sample, inspect it, then finish the remaining strips and wire their frame ranges into Tokyo's movement states.
